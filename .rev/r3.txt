**What's correct.** Several of the fixes hold up well under attack, and it's worth saying so:

- **Rollback is applied consistently to both engines** — `base_interpreter._execute_transition` and `sync_interpreter._process_single_transition` snapshot and restore identically; differential probes agreed on every configuration I tested.
- **Plugin `on_transition` is correctly suppressed on a failed transition** (it sits after the `try` block), so observers never see a phantom transition.
- **Transient-settling interaction is sane**: when `a→b` succeeds and `b`'s `always→c` fails, the machine correctly lands on `b`, not `a` — per-transition snapshots are the right granularity.
- **`_SafePlugin` containment is sound**, including the duck-typed missing-hook path and the `__eq__`/`__hash__` work needed to keep `in` checks and `list(plugins)` behaving.
- **The `CancelledError` re-raise ordering is correct** in both `_run_event_loop` and `_execute_actions`; `stop()` still owns the status transition, and the reasoning in the comment about not setting status in the cancellation path (to avoid skipping actor teardown) is right.
- **The rollback itself cannot realistically raise** — `set.clear()`/`set.update()` on an existing set are non-throwing.
- **All 2675 tests pass.**

The two things I'd block the v0.6.0 release on are finding #1 (a straight data-loss regression against `main` on the most common code path in the library) and #3 (an unbounded task leak). Findings #2 and #3 share a root cause worth fixing together: the rollback restores *membership* but not the *scheduled work* that membership entails, so a correct fix needs to re-schedule tasks for restored nodes and cancel tasks for rolled-back ones, not just swap the set.
