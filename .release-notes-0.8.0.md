**Fortify.** 0.8.0 is not about one headline feature. It systematically hardens the engine — the way a production system needs a library to be hardened before it can be trusted with money or safety.

The trigger was a trading-terminal adoption audit that filed 34 defects against 0.7.0 with a single theme: *the library failed silently by default*. A dropped event, a half-applied transition, a guard that raised and was treated as `False`, a timer starved behind a busy inbox — each looked like normal operation. 0.8.0 closes all 34, then keeps going: an adversarial audit of the result, executable documentation, real type safety, and a measured performance pass.

Every new behaviour is a per-machine policy or an additive API whose default preserves 0.7.x semantics, with two deliberate exceptions under **Changed**.

> [!IMPORTANT]
> **Two 1.0 deprecations start now.** `actionErrorPolicy` still defaults to `"continue"` but emits a one-shot `DeprecationWarning`; it flips to `"rollback"` in 1.0. `create_machine(strict_targets=False)` — the 0.7.x escape hatch for unresolvable targets — is removed in 1.0. Set both explicitly in production machines.

### What "fortify" means, concretely

| Weak point in 0.7.0 | 0.8.0 |
|---|---|
| A raising action left a half-applied transition committed | `actionErrorPolicy: "continue" \| "rollback" \| "fail"`; rollback restores configuration *and* context, and stops actors the failed transition spawned |
| Unknown events, raising guards, unhandled events vanished silently | `onUnhandled`, `guardErrorPolicy`, `strict` mode (`UnknownEventError` **at the call site**, with did-you-mean), opt-in `event_schemas` payload validation; a `PluginBase` hook for every failure path |
| Bad targets and dead `always` loops surfaced at runtime, if at all | Rejected at `create_machine()`, every finding in one message |
| Unbounded, unobservable inbox | `max_queue_size` + `OverflowPolicy.RAISE \| BLOCK \| DROP_NEWEST`, `queue_depth`, `on_event_dropped` |
| `send()` was fire-and-forget only | `await send(e, wait=True)` → `Receipt(state_ids, changed, error)`; `send_priority()` jumps the backlog |
| `raise` queued behind external events | SCXML internal queue: a self-raised event is a microstep |
| Snapshots had no version, no identity, lost the pending inbox | Envelope v1 (`version`, `machine_id`, `machine_hash` → `SnapshotDriftError`); inbox and deferred events persist; `from_snapshot(restart_services=True)` + `pending_invocations()` |
| `after` timers starved under load; sync timers ran on unlocked threads; no virtual time | Injectable `Clock`: `SimulatedClock` for deterministic tests, `RealClock` with a priority lane (500 busy machines: ~46 ms late, was ~180); sync timers fire on the caller's thread |
| Actors: 2 tasks + a 5 ms poll per child, done machines never reaped, `spawn_blocking_` ignored on async | Completion future; terminal machines torn down; both engines honour `spawn_blocking_`; `invoke.input` may be a callable |
| Two engines, two copies of the algorithm, bugs in one but not the other | One core algorithm on `BaseInterpreter`; the sync engine drives it to completion and structurally cannot drift |
| `py.typed` shipped, but `interp.context` was `Any` and a TypedDict context was a type *error* | `create_machine(context_type=MyCtx)` flows to `interp.context`; `send(wait=True)` types as `Receipt`; `MachineLogic` callables pin arity. Zero mypy/pyright errors; a test type-checks *user* programs and fails on any false positive |
| Documentation drifted from the code | Every ```python block in the README and 26 guide pages is **executed in CI**; every link resolved; 34 runnable feature examples |

Plus: hierarchical `interp.value`, `send_threadsafe()`, and +40–55 % events/s on every machine shape from build-time indexing.

### Numbers
- **3,183 tests** on Python 3.9–3.14, Linux/macOS/Windows. The audit's 31 repro scripts run in CI on every push.
- **CLI:** 4,160 generate-and-*execute* combinations over the 104-machine Stately corpus pass; the only non-zero exits are invalid source machines the engine correctly rejects. Five generator defects fixed (Stately `inline:` names, `"!guard"`, compound `onDone`, stdlib-shadowing filenames, non-ASCII names).
- **Benchmarks** vs `transitions`, `python-statemachine`, `sismic` (`benchmarks/competitors/`): fastest on every statechart-shaped scenario — 3–8× on nested, parallel and timers. `transitions` remains faster on flat machines because it does not run a statechart algorithm; the docs say so.

### Upgrading from 0.7.0
No code changes required.
- `Interpreter[Ctx]`, not `Interpreter[Ctx, Any]` — the unused second type parameter is gone. Untyped code is unaffected.
- A `SimulatedClock` shared between an async parent and a `SyncInterpreter` child now works (it raised before).
